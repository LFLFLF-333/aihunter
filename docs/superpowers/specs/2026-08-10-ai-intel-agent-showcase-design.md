# AI情报员公开展示页设计规格

## 1. 项目目标

创建一个可公开访问的单页网站，用于展示“AI情报员”的价值、工作流程、真实成果、质量规范和能力边界。访客可以体验一段预设的模拟对话，但网站不连接 Hermes、飞书、模型 API 或任何私人数据，也不允许访客调用真实 Agent。

首版发布到免费的 Vercel 域名。流程为：本地完成并预览，用户确认后才创建或上传 GitHub 仓库，随后部署到 Vercel。

## 2. 目标受众

- 圈友和同行：理解设计思路、工作流和复现方式。
- 潜在客户：看清业务价值、交付成果和人工节省。
- 招聘方或评委：评估 Agent 架构能力、质量控制和真实落地结果。

## 3. 方案比较与选型

### 方案 A：纯静态案例页

优点是开发快、风险低、信息清楚；缺点是缺少“真实 Agent”体验，难以体现审批和发布逻辑。

### 方案 B：连接真实 Agent 的在线体验

优点是体验最真实；缺点是会引入 API 成本、滥用、权限、隐私、速率限制和提示注入风险，不符合“不接 API、他人无法调用”的要求。

### 方案 C：静态展示页＋前端模拟对话（采用）

使用本地静态数据驱动模拟交互。访客可以点击预设任务并观看处理阶段，但所有结果均来自打包在网页内的演示内容。该方案兼顾真实感、安全性、加载速度和低维护成本。

## 4. 视觉方向

采用用户确认的“产品演示＋案例档案”方向：

- 明亮、专业、克制，避免夸张的赛博视觉。
- 首屏突出价值和真实量化结果。
- 中段用模拟对话建立产品体验感。
- 后段用真实案例、质量规范和能力边界建立可信度。
- 桌面端有完整叙事，移动端保持清晰的单列阅读体验。

## 5. 页面结构

1. **首屏价值主张**：Agent 名称、一句话定位、人工耗时对比、安全演示标识和体验按钮。
2. **模拟对话体验**：访客点击预设指令，依次看到输入解析、联网检索、来源核验、内容生成、人工审批、模拟发群六个阶段。
3. **真实成果**：展示 2026 年 8 月 1 日至 8 月 9 日已经生成并发布的 AI 情报长图及文字摘要，明确标识为真实历史产物。
4. **效率对比**：人工约 4.5–8.5 小时，对比最近一次 Agent 完整运行约 40 分钟，加人工审核约 5–15 分钟。
5. **核心能力**：检索、核验、筛选、分析、结构化写作、长图生成、审批后发布。
6. **质量规范**：时间范围、来源可信度、事实与判断分离、去重、栏目完整性和三项交付物一致性。
7. **能力边界**：不连接真实 API、不访问私人数据、不允许公开调用、不未经批准发布、不提供投资或合规决策。
8. **工作原理与使用说明**：说明 Codex、Hermes 和飞书的职责，以及真实 Agent 的触发、审核和发布方式。
9. **页尾声明**：这是公开展示和模拟体验，不是在线服务入口。

## 6. 模拟体验设计

### 可操作范围

- 访客只能选择预设指令，例如“整理 8 月 1 日至 8 月 7 日的 AI 情报”。
- 访客可点击“开始体验”“查看来源”“确认发布”等演示按钮。
- 页面以动画和状态卡展示六个处理阶段。
- “确认发布”只切换为模拟成功状态，不发送任何网络消息。

### 明确禁止

- 不提供自由文本输入后端。
- 不调用任何模型或搜索 API。
- 不连接 Hermes、飞书机器人或本地文件系统。
- 不在前端代码中存放密钥、Token、群 ID、用户 ID或内部路径。
- 不提供能够被误认为真实发布的按钮或文案；所有模拟结果必须带“演示”标识。

## 7. 技术架构

采用静态 React 前端，推荐 Vite 构建并由 Vercel 静态托管。

- **页面组件层**：首屏、模拟对话、案例、效率、能力、规范、边界、架构和页尾。
- **演示状态层**：浏览器内有限状态机控制六阶段体验和人工审批分支。
- **内容数据层**：公开展示文案、脱敏后的真实案例摘要和演示步骤，全部作为本地静态数据随构建产物发布。
- **媒体层**：使用项目中已经生成的真实长图，发布前检查并移除可能包含的内部路径、私人标识和敏感信息。
- **部署层**：GitHub 保存公开网页源码，Vercel 从仓库构建并发布免费公开网址。

网站不设置服务端函数、数据库、身份认证、API 路由、Webhook 或分析追踪。除加载网站静态资源外，访客操作不产生外部数据传输。

## 8. 数据流

1. 浏览器加载静态页面和演示数据。
2. 访客选择预设任务。
3. 前端状态机依次展示六个模拟阶段。
4. 访客点击模拟审批。
5. 页面显示“已模拟发布”的结果和安全提示。
6. 页面刷新后恢复初始状态，不保存访客内容。

## 9. 异常与降级处理

- JavaScript 不可用时，页面仍显示 Agent 定位、能力、规范、边界和真实案例；只关闭模拟交互。
- 长图加载失败时显示可读的替代说明，不显示空白区域。
- 动画被系统设置为“减少动态效果”时，改用即时状态切换。
- 小屏幕下所有并排模块改为单列，避免横向滚动。
- 部署构建失败时不得宣称已上线，必须保留本地预览并报告错误。

## 10. 安全与隐私

- 上线前扫描源码、静态资源和 Git 历史，排除 API Key、Token、Cookie、群 ID、用户 ID、本地绝对路径和聊天记录。
- 只发布用户确认可公开的岗位信息、流程说明和脱敏案例。
- 不上传 Hermes Profile 运行目录、`.env`、日志、Session 备份或飞书配置。
- GitHub 仓库只包含展示网站所需文件，不包含完整 Agent 运行环境。
- 页面显著标注“模拟体验，不连接真实 Agent”。

## 11. 验收标准

- 访客在首屏 10 秒内能理解 Agent 是什么、解决什么问题。
- 模拟流程可以从任务输入完整运行到模拟审批和模拟发布。
- 页面清楚展示真实产物、人工节省、核心能力、质量规范和能力边界。
- 所有交互均不调用真实 API，也不发送或保存访客数据。
- 桌面端和移动端均无明显溢出、裁切、乱码或不可读内容。
- 页面通过键盘操作，文本和主要控件具备合理对比度。
- 构建成功且本地预览通过后，必须由用户明确确认才能上传 GitHub。
- GitHub 上传成功后，才允许部署到 Vercel。
- 最终提供 GitHub 仓库链接和 Vercel 公开网址。

## 12. 不在首版范围内

- 真实 AI 对话或联网检索。
- 用户注册、登录和账号体系。
- 数据库、后台管理或内容管理系统。
- 联系表单、支付、订阅或商业线索收集。
- 访问统计和第三方追踪脚本。
- 多语言版本。
